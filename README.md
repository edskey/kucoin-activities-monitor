# KuCoin Activities Telegram Monitor

Независимый Telegram-бот для мониторинга русскоязычных разделов [«Последние мероприятия» KuCoin](https://www.kucoin.com/ru/announcement/activities) и [Events Hub](https://www.kucoin.com/ru/events-hub). GitHub Actions запускает проверку каждые пятнадцать минут, а защищённая Vercel Function хранит состояние в Upstash Redis и отправляет новые карточки в Telegram.

## Что считается новым событием

- Источник — официальный публичный KuCoin API `GET /api/v3/announcements` с категорией `activities` и языком `ru_RU`.
- Для каждой карточки открывается её публичная русская страница и читаются период акции и призовой пул.
- Текущей считается акция, у которой период уже начался и ещё не закончился.
- Если KuCoin не указал распознаваемый период, карточка считается текущей 30 дней после публикации, а таймер выводится как `не указан`.
- Стабильный идентификатор события — `annId` KuCoin. Остаток времени, размер пула, заголовок и другие изменяемые поля в идентификатор не входят.
- Каждая новая карточка отправляется отдельным сообщением.

Для Events Hub:

- используется публичный JSON endpoint самой страницы `GET /_api/growth-campaign/api/campaign/list`;
- параметры `bizStatus=1`, `tab=` и `hot=0` соответствуют фильтрам «Текущие → Все»;
- для каждой карточки открывается её публичная русская страница `/ru/campaigns/<code>`, откуда извлекается полный призовой пул;
- API-время начала и окончания проверяется повторно, поэтому будущие и завершённые карточки не принимаются даже при ошибочной выдаче endpoint;
- стабильный ID — ID карточки Events Hub, таймер в него не входит.

На текущей версии страницы KuCoin нет буквального переключателя «Все → Проходят сейчас». Монитор воспроизводит это состояние по датам из текста публикаций, а не с помощью нестабильных CSS-классов или браузерной автоматизации.

## Исключение дублей

- Внутри Events Hub повторные карточки исключаются по ID, коду кампании, канонической ссылке либо одинаковому нормализованному заголовку с датой окончания.
- Между Events Hub и объявлениями используется общий код ссылки `/campaigns/<code>`, который KuCoin размещает в тексте объявления и в карточке Hub.
- Принятые межисточниковые ключи сохраняются в общем состоянии этого бота. Поэтому одна и та же акция не будет отправлена повторно, даже если позднее останется только в одном из двух разделов.
- При совпадении приоритет имеет источник объявлений, а оба исходных ID отмечаются обработанными только после успешной доставки одного сообщения.

## Формат сообщения

```text
🔥 Новая промоакция KuCoin

🔵 Название: Кампания по листингу AEON (AEON) — розыгрыш 310 000 AEON
🔵 Объем пула: 310 000 AEON (≈ 620 000 USDT)
🔵 Заканчивается через: 5д 0ч 0м

🔵 Ссылка: Открыть
```

Для USDT и USDC сумма передаётся без пересчёта. Для других токенов используется цена CoinGecko в USD и показывается как приблизительный эквивалент в USDT (`≈`). Если CoinGecko не может однозначно найти токен или получить цену, нативная сумма сохраняется, а в сообщении указывается, что оценка в USDT недоступна.

## Первая проверка

Первый успешный вызов `/api/check` сохраняет текущие ID отдельно для каждого источника и ничего не отправляет. Поэтому при первом включении Events Hub его существующие карточки также станут базой без уведомлений. Пустой список сохраняется как полноценная база. Уведомления начинаются только для карточек, которые впервые появились в следующих проверках.

## Изоляция от других ботов

Проект использует отдельные переменные с префиксом `KUCOIN_` и только следующие ключи в общей Upstash Redis:

- `kucoin-activities-monitor:state:v1`
- `kucoin-activities-monitor:lock:v1`

Поэтому его состояние и блокировка не пересекаются с другими ботами в той же бесплатной Redis-базе.

## Секреты Vercel

Добавьте в Environment Variables отдельного Vercel-проекта:

- `KUCOIN_TELEGRAM_BOT_TOKEN`
- `KUCOIN_TELEGRAM_CHAT_ID` — `@channel_name` или ID канала, обычно начинающийся с `-100`
- `KUCOIN_CHECK_SECRET` — длинная случайная строка
- `KUCOIN_UPSTASH_REDIS_REST_URL`
- `KUCOIN_UPSTASH_REDIS_REST_TOKEN`
- `KUCOIN_STATE_TTL_SECONDS` — необязательно, по умолчанию 2 592 000 секунд

Бот должен быть администратором Telegram-канала с правом публикации сообщений.

## Секреты GitHub Actions

Добавьте в Actions Secrets:

- `KUCOIN_VERCEL_CHECK_URL` — полный HTTPS-адрес `https://<project>.vercel.app/api/check`
- `KUCOIN_CHECK_SECRET` — то же значение, что и в Vercel
- `KUCOIN_COINGECKO_DEMO_API_KEY`

Пароли, cookies и пользовательская сессия KuCoin не нужны и не используются.

## Локальная проверка без Telegram

```bash
npm test
npm run collect
```

Тесты подменяют Telegram, Redis, KuCoin и CoinGecko локальными ответами. `npm run collect` только печатает JSON в стандартный вывод и не обращается к Telegram или Redis.

## Развёртывание

1. Создайте отдельный Vercel-проект из этого репозитория на Hobby и добавьте Vercel-переменные.
2. Подключите существующую Upstash Redis-базу через её REST URL и token.
3. После первого Vercel deployment добавьте GitHub Actions secrets.
4. Один раз вручную запустите workflow `Check KuCoin activities` и убедитесь, что ответ содержит `sent: 0` — это создаст базу без сообщений.
5. После этого расписание `*/15 * * * *` будет запускать проверки автоматически. GitHub Actions может запускать задачи с небольшой задержкой относительно точной пятнадцатиминутной отметки.

Обычный плановый запуск не отправляет синтетические сообщения и не содержит команд ручного deployment.

## Ручные тестовые сообщения

Workflow можно вручную запустить с одним из независимых флагов:

- `send_test_messages` создаёт отдельную тестовую базу `kucoin-manual-test` и отправляет 10 разных сообщений с пометкой `[ТЕСТ]`;
- `send_events_hub_test_message` создаёт отдельную базу `kucoin-events-hub-manual-test` и отправляет одно сообщение `[ТЕСТ EVENTS HUB 1/1]`.

Плановые запуски тестовые режимы не используют.
